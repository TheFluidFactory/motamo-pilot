# MOTAMO architecture

## Load order

1. Namespace
2. Central configuration
3. Content data
4. Utilities, storage and state
5. Reusable UI components
6. Answer rules
7. Screen renderer
8. Game engine
9. Bootstrap

All files use the shared `window.Motamo` namespace. This keeps the project compatible with plain GitHub Pages and avoids a bundler while still separating responsibilities.

## Examples

### Add a level

Add one object to `js/data/levels.js`. The level selector and progress calculation read from that central array.

### Change the number of displayed level tiles

Change `levelsPerDifficulty` in `js/config.js`. Every difficulty section updates together.

### Change the keyboard layout

Change `keyboardRows` in `js/config.js`. Both the question keyboard and the final-word keyboard are generated by the same component.

### Add a mission

Add one object to `js/data/missions.js`. `createMissionCard()` in `js/ui/components.js` renders it using the existing shared design.

### Change answer-block appearance

Edit `.answer-slot` once in `css/styles.css`. Question answers and the final word use the same shared styling.

### Change helper-letter logic

Only edit `js/game/answers.js`. The game engine consumes that API without duplicating the logic.

## Boundaries

- Data files contain content, not gameplay operations.
- Components create repeatable UI, but do not decide game outcomes.
- The answer module handles normalization and correctness.
- The engine controls progression and outcomes.
- The bootstrap file only initializes the app.
